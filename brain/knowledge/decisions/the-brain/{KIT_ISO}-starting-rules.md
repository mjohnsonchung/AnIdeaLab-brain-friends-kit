# The rules this brain started with

**Decided** {KIT_DATE}, by Matt, who made the starter kit this brain was started from, in a Claude Code session in his own brain. They're a starting point: the owner can change any of them, and their own decisions win.

## Where they came from
Matt runs his own second brain: AI agents working on his businesses, with a core every agent reads and two libraries. He made this kit so friends could start one the same way, with "a little bit, not more restrictions necessarily, but our one's intentionally more stripped back and free than theirs would be". He asked for the same structure and rules where they help, without being "overly constraining".

## Kept from Matt's brain
- **Rules about how are defaults** (Matt, 16 Oct 2026): the agent picks the host, tool, service or format, and says why when it changes one.
- **Reuse before you build** (17 Oct 2026): use existing code, say what was used, and ask before GPL or AGPL code goes into anything sold.
- **PC work goes to the PC,** through a GitHub Actions runner (17 Oct 2026), so needing a GPU or the owner's apps never rules a route out.
- **Give the owner a command** (22 Oct 2026). Matt: "just give me a powershell command to run. also, make that the default option for tasks like this that involve my computer". He asked for the same here: a task on the owner's computer runs through the runner, or as one command to paste, before click-by-click steps.
- **Not tied to one AI provider** (18 Oct 2026): plain Markdown, relative links and plain scripts.
- **No Claude artifacts** (24 Oct 2026). Matt: "if you're going to refer to a Claude artifact or any other kind of AI artifact, that wouldn't exist to an separate agent in the GitHub repo. Or with access to my computer... That agent would still be able to get it. So no Claude artifacts. Anymore." He wanted the same here. So what the brain saves or points to lives in its repo, on the owner's PC or in another place any agent can reach, and a page for the owner is an HTML file saved there.
- **Ship it yourself** (16 Oct 2026): push and publish when a change works; git history is the safeguard. Here it starts once the owner has said go.
- **One check is enough** (20 Oct 2026). Matt: "We just need a quality check most of the time, just one, if that... for like complex tasks, then obviously, yeah. Can do with more checks", "no matter what a tool or mode suggests". For this kit he called it "the new kind of decision that one review is enough unless it's for extremely complex tasks".
- **No rules about personal information** (Matt, 18 Oct 2026 for his own brain; for this one, 27 Oct 2026): the owner's details, and those of the people in their life and work, go in the brain like any other note. Matt, bringing it here: "You want to free the brain. You want it to be the hub, so it can hold whatever, like mine", since a rule against it "stops them from using the brain the way they want to and is unecesarily restrictive on agents and inefficient too re token use". The secrets gate still keeps keys, passwords and card details out.
- **The gates:** money (spending needs the owner's go; agents never pay or refund), secrets (keys only in GitHub's Actions secrets or a host's secret settings, never in files or chat), the sign-off on outside messages ("Assistant built by AnIdeaLab.com", never on replies to the owner; Matt: "keep the sign off on outside messages", and on 23 Oct 2026 he called it the owner's return for "their free use of the brain and the research that went into making it"), and the owner's voice (never answer for them).
- **Keys in one command** (Matt, 26 Oct 2026 for his own brain; for this one, 31 Oct 2026): the [add-a-key skill](../../../skills/add-a-key/SKILL.md), where the owner pastes one command that opens the page that makes the key, reads it in hidden and saves it in the brain's GitHub secrets. Matt, on his own: "That was a very streamlined way of doing it... Being able to add a GitHub token that way. And whatever else, wherever else." Bringing it here: "Yeah, definitely add the add a key skill."
- **Commit straight to main,** small commits, never force-push.
- **No co-author lines** (Matt, 27 Oct 2026 for his own brain; for this one, 31 Oct 2026): commits and pull requests carry no Co-Authored-By, session link or "Generated with" line. Matt, on his own: "turn off that co-authored thing"; bringing it here: "And yeah, the setting that keeps co-authored bylines out of commits." Claude Code's setting is off in `.claude/settings.json`, and the core says it too, because a cloud session is told to add the lines unless the brain's own rules say otherwise.

## Added for this brain
- **Guide mode** (Matt, 22 Oct 2026): "somewhat of like a beginner mode... the conversation wouldn't expect that they know what they're doing", with plans confirmed before work and check-ins along the way, "because there's only so much usage that the person gets". Jobs are sized by complexity, not tokens: if estimates were "going to be like wildly off... it's not worth even including, they're just going to have to figure out over time like what makes a good prompt". The [guide-mode skill](../../../skills/guide-mode/SKILL.md) has the how. It tunes down rather than turning off (Matt, 31 Oct 2026): "I think guide mode, just in general, is a great skill to have, but maybe instead of turning it off, it's like it like tunes it down, like the tutorial kind of vibe." Tuned down, agents still size each job, split big ones into stages and hand off at the end of each, without the explaining; Matt's own brain runs it that way.
- **Best guess, light checks** (Matt, 24 Oct 2026). On a game he was building: "best guess 2 pass kinda thing, not toooo much verifying, ill do that after when playing". He wanted the same here, "but just a minimumal amount of checks/verifying needed for the task at hand". The two passes, a best-guess go and then one fix-up pass, are the agent's reading of "2 pass". It sits alongside "one check is enough".
- **One or two agents at a time** (Matt, 24, 29 and 31 Oct 2026). On 24 Oct: "agents should only run on one thread, even for like a complex task. Like they can spawn one agent and it can run to completion, and then they can spawn another agent", because "splitting up complex tasks like that is definitely useful between agents memory wise", but not "multiple agents, having them all work in parallel. It's just for usage, consumption, and yeah, it's just better for users. At least for now." It's a default: "the person whose brain it is could do that", change it. Matt's own brain allows a few agents at once. On 29 Oct 2026 Matt gave the reasons for handing work on, and asked for them here too: "The friends kit one should copy this rule as well, because ultimately, if you can save on context like that, like handing off a task to another agent like that, with like a specific handoff amount, so that they're not taking in the whole context of the whole conversation, then that's an efficient way to do things too, you know. That saves their usage too." On 31 Oct he loosened it: "I don't want it to be stuck to only one agent all the time. It's just like, I don't want it to run too many threads at the same time", then "I just want to say default is one or two at a time, and running more than that needs the owner's yes. There's no limit on that", and "the agent should still ask before running several at once if the owner's turned guide mode off". So the core's line lists the uses, one or two at a time by the agent's call and more with the owner's yes, and the brain spec's [handing work to an agent](../../../skills/brain-spec/SKILL.md#handing-work-to-an-agent) gives each one's reason.
- **60 general skills,** and the way to get more (Matt: "just give them general basic skills. They can decide which ones they want further than that. But give them the way to get good quality skills that we've done"): the [find-skills skill](../../../skills/find-skills/SKILL.md). Since 27 Oct 2026 there are 61: the kit's own [windows-powershell skill](../../../skills/windows-powershell/SKILL.md) joined them, the traps in Windows PowerShell that kept breaking agents' scripts in Matt's brain ("it keeps tripping you up"). Since 31 Oct 2026 there are 63, with the upload-point skill below and add-a-key above.
- **The upload point** (Matt, 31 Oct 2026): a small window on the owner's PC, and My brain in Send to, "for them to put files or folders or whatever they want into there", listed by path on GitHub for an agent to sort into the brain. "Sorting should move files, not copy them", and a code repo is learned where it is, "so the agent is sufficiently prepared to work on those projects if asked". Windows only for now; a Mac version is still to come. How: the [upload-point skill](../../../skills/upload-point/SKILL.md).

## Left out on purpose
- Matt's own notes, people, projects and tasks.
- Matt's looser rules for his own brain: few gates on what the brain makes, says and offers, and legal work being the agent's call. They suit him ("we're quite lax on legal stuff specifically, because, you know, I'm a lawyer"). This brain runs on the agent's own normal judgement for those, with nothing added either way (Matt: "just the default kind of setting. You don't have to build anything extra in").
- Matt's own names (Farm Town, his ventures, his PC's name).
